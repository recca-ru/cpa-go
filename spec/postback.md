# Контракт: подпись S2S-постбэка CPA

Приём результата конверсии от рекламодателя. Подпись доказывает, что постбэк
пришёл от владельца секрета оффера.

Источник правды — `apps/backend/src/utils/cpa-postback-signature.ts` платформы.
Векторы в `testdata/signature_vectors.json` порождены им же.

## Каноническая строка

Поля соединяются двоеточием. **Число сегментов однозначно называет форму:**

```
5   click_id:external_id:status:sum_rub:sub_id                легаси
6   click_id:external_id:status:sum_rub:sub_id:goal           легаси + цель
7   click_id:external_id:status:sum_rub:sub_id:goal:timestamp полная
```

Правило выбора формы:

| Что передано | Форма |
|---|---|
| ни цели, ни метки времени | 5 сегментов |
| цель передана (**любым значением, включая пустую строку**) | 6 сегментов |
| метка времени передана | **всегда 7**; цель едет пустой строкой, если её нет |

⚠⚠ Решает **присутствие ключа**, а не его значение. Живые интеграции, не знающие
о целях, продолжают подписывать пять сегментов, и их подписи валидны без правок.
Это осознанное свойство контракта, а не случайность реализации.

⚠⚠ Метка времени **форсирует** длинную форму намеренно. Наивное «дописать метку
в хвост» дало бы шесть сегментов и для цели, и для метки, а отличить их по
содержимому нельзя — цель бывает числовой. Проверяющий ошибался бы молча, то
есть на деньгах.

## Три состояния — почему в Go нужны указатели

У трёх полей «не передали» и «передали пустым» означают **разное**, и Go-типы
`string`/`int64` этой разницы не выражают:

| Поле | «не передали» | «пусто / ноль» | Тип в Go |
|---|---|---|---|
| `goal` | 5 сегментов | `""` → 6 сегментов | `*string` |
| `sum_rub` | сегмент `""` | `0` → сегмент `"0"` | `*string` |
| `sub_id` | сегмент `""` | `""` → сегмент `""` — совпадает | `string` |

⚠⚠ **`sum_rub` — именно `*string`, а не денежный тип.** Первая редакция этой
таблицы говорила `*RUB`, и это противоречило абзацу «Сумма» строкой ниже:
вектор `sum_fractional` несёт `12.5`, а в `int64` дробь не представима вовсе.
Подпись здесь — СТРОКОВЫЙ протокол: в канон уходит лексическая форма, как её
дал отправитель, и любое приведение к числу с обратным форматированием ломает
её молча. Денежный тип `RUB` — про суммы в ответах API, не про эту подпись.

`sub_id` — единственное, где состояния совпадают, поэтому он обычная строка.
Схлопнуть `goal` или `sum_rub` до значения значит молча менять число сегментов и
получать подпись, которой сервер не ждёт.

## Сумма

В канон уходит **лексическая форма, как её дал отправитель**: `1000` остаётся
`1000`, `12.5` остаётся `12.5`, `0` остаётся `"0"`, отсутствие — пустой строкой.
Собственное форматирование дробей (округление, фиксированные знаки, локаль)
разойдётся с подписью сервера — вектор `12.5` закрепляет именно это.

## Подпись

```
signature = HMAC-SHA256(secret, canonical)   →   hex, НИЖНИЙ регистр, 64 символа
```

Секрет оффера имеет вид `cpaps_<32 hex>`.

### Проверка

1. Подпись обязана быть строкой из **ровно 64 hex-символов** — иначе сразу `false`,
   не доходя до сравнения.
2. Сравнение — **константное по времени** (`hmac.Equal`). Оператор `==` раскрывает
   подпись по времени ответа.
3. Ротация секрета неразрушающая: у оффера бывает **предыдущий** секрет, живущий
   7 суток. Проверка на стороне платформы пробует оба слота; клиенту достаточно
   уметь подписывать текущим.

## Токен GET-двери

Отдельная дверь принимает `?secure=<токен>`, где

```
token = "cpag_" + HMAC-SHA256(secret, offer_id)   →   hex
```

Префикс `cpag_` обязателен и отличает токен от самого секрета: боевой секрет
начинается с `cpaps_`, и по первым символам их видно в журнале.

⚠ Сам `postback_secret` в строке запроса не ездит **никогда** — она целиком
попадает в журналы nginx, в `Referer` каждого подресурса и в аналитику любого
посредника. Токен производный: ротация секрета отзывает его автоматически.

## Свежесть

`CheckFreshness(ts, now, tolerance)` — истина, когда `|now − ts| ≤ tolerance`.
Допуск по умолчанию на стороне платформы — **300 секунд**. Метка времени в
секундах Unix.

## Ошибки, которые вернёт дверь

| HTTP | code | когда |
|---|---|---|
| 401 | `BAD_SIGNATURE` | подпись не сошлась ни с текущим, ни с предыдущим секретом |
| 401 | `BAD_SECURE` | токен GET-двери не сошёлся |
| 400 | `STALE_TIMESTAMP` | метка вне допуска |
| 429 | `RATE_LIMITED` | 60/оффер или 300/адрес в минуту, `Retry-After: 60` |
